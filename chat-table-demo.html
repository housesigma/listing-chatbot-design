Wide-table rendering — chat bubble overflow strategies

把同一张 10 列的房产对比表放进 320px 宽的气泡里。 五个面板：同一份 HTML，只换 CSS，渲染结果天差地别。

递进顺序：0 现状（squeeze） → A table 自身横滚 → B wrapper 横滚 → B+ 加渐变提示 → C 第一列粘性。

💡 在每个气泡里横向拖动表格，留意右边缘视觉提示和列宽行为

0 · CURRENT

现状 — squeeze + wrap

display:block; width:100%; overflow-x:auto + 单元格 white-space:normal。
浏览器选了"压缩列宽 + 文字换行"，不会触发横滚。

📊 周边可比销售

  • 列名被竖切（"List / Price"、"Sold / Price"）
  • 数字与货币列被强行换行，难以扫读
  • 列越多压得越扁，到 12 列基本不可读
A · TABLE-SCROLLER

A — table 自己当滚动容器

width:max-content（自然宽） + max-width:100% + 单元格 nowrap。总宽超出气泡 → 触发横滚。

📊 周边可比销售

  • 一处 CSS 改完，无需改 marked renderer
  • 列宽按内容自然伸缩，整齐
  • 所有列强制 nowrap → 长地址 / 备注列变成一根长条
  • display:block 丢失部分 table-layout 算法（colgroup、align 不可靠）
B · WRAPPER

B — 外层 div 当滚动容器

marked renderer 在 <table> 外包一层 <div class="md-table-wrap">。table 保持 display:table，列宽算法不丢。

📊 周边可比销售

  • 语义保留 — table 还是 table，colgroup / scope 都正常
  • tabindex="0" 让键盘用户也能滚到溢出列
  • 需要改 marked renderer（一行）
  • 缺少"还能滚"的视觉暗示，新用户易漏
B+ · FADE MASK

B+ — 右侧渐变提示

B 之上加 mask-image：右边缘 28px 线性渐隐到透明。 用户一眼看出"还能横滚"。

📊 周边可比销售

  • 视觉暗示零交互成本，纯 CSS
  • 滚到最右时渐变会自然消失（隐含反馈）
  • 表格不溢出时仍渲染渐变 → 需要 JS 检测溢出后加 class，或接受小瑕疵
  • 低端 Android WebView 上 mask 偶有锯齿，需要 fallback
C · STICKY-LEFT

C — 第一列粘性 + B+

在 B+ 基础上对第一列 position:sticky; left:0。 横滚时地址列始终可见，方便对齐数据扫读。

📊 周边可比销售

  • 多列横滚体验最佳，类 Excel 冻结首列
  • sticky 列加 box-shadow 模拟 z 轴层次
  • 必须 border-collapse:separate，边框处理变啰嗦
  • sticky 单元格背景必须不透明，否则下层文字穿透
marked.js renderer override（方案 B / B+ / C 共用）
// useChatStream.ts — 紧邻现有 new marked.Marked(...) 处
const renderer = new marked.Renderer();
const origTable = renderer.table.bind(renderer);
renderer.table = (...args) =>
  `<div class="md-table-wrap" role="region" aria-label="表格" tabindex="0">${origTable(...args)}</div>`;

const _marked = new marked.Marked({ breaks: true, gfm: true, renderer });
